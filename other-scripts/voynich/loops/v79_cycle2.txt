v79 cycle 2: IS THE LINE-START MARK A CLASS TAG OF ITS LINE, OR A CATCHWORD? (6 Oct 2026). Script: tools/v79_c2.py. Checkpoints: data/v79_ckpt/c2_*.pkl.
Design: ~6,000 random binary features of a line's BODY (words 2..n only; the first word, which carries the mark, never enters): any of a random set of 1-8 word types, of 1-5 glyph bigrams, a random glyph set at the start of word 2 or 3, at the line-final glyph. Each is predicted from the mark (line-initial glyph) on top of a stratum = section|language x line mode (v67: majority first-glyph class of the body words) x line length band, so the known line-mode effect cannot count. Held-out bits per 1000 lines gained by the mark on the 50 features chosen on the other leaf half (both ways). Variants: SAME (mark -> own body), NEXT (mark -> body of the line below, with that line's own mark in the stratum), PREV (catchword: body of the line above -> this mark, with the mark above in the stratum, so the known chain cannot count). Nulls (8 each): marks shuffled within paragraph (line-level) and within page (paragraph-level).
Controls (opaque v72 surface, mark on 80% of lines): C_PART = Brumati, the real part of the entry each line belongs to (header/description, then further paragraphs: synonyms, habitat, uses), a line-level structural mark; C_CLASS = Brumati, the entry's real Linnaean class on every line (a paragraph-level class letter); N_DANTE = verse numbers (a mark with no content link). Generators SELFCIT, MK2, JUNC, STACK fitted to ZL3b.
