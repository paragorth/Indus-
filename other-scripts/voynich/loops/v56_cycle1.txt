v56 THE BOOK IS HYPERTEXT, cycle 1 (5 Oct 2026): blind arithmetic pointer rules
Tools: tools/v56_lib.py, tools/v56_kernel.c (C scorer), tools/v56_c1.py, tools/v56_report.py, tools/v56_inspect.py
Checkpoints: data/v56_ckpt/c1_*.json, c1_*.log (git-ignored)
Prior-art check: LITERATURE.md, FINDINGS.md, STRATEGIES.md have no pointer or cross-reference test. A web search turned up only
rare-token "hub folio" networks (e.g. f86v linked to many sections), and no attempt to decode words as page addresses.

Machinery. R[i,t] = how much the rare payload skeletons (frame o a i n y l r + gallows; padding q, e, d, ch/sh dropped) in the
5 lines around token i (the token itself removed) are shared with page t. It is a residual against pages of the same section and
Currier language at the same distance band, the own page and +-2 pages are zeroed, and each column is centred so that hub pages
earn nothing. Rule = selector x feature (glyph counts, alphabetic-numeral values 1-9/10-90/100-900, or positional base 2-12 over the
skeleton or the full word) x address (page / folio / quire, absolute mod or clip with a learned offset, or relative forward/back).
Score = sum R[i, target_i] minus the expectation when the same targets are shuffled among the same tokens (this kills class-hub
rules), / sqrt(n). Search: grid of 3,330-3,700 configs in a fixed random order, 300 random value vectors each, then 4 coordinate-
ascent starts (every candidate value of one glyph scored at once in C), offset/mod ascent, and subset-selector refinement. Held-out =
WORD TYPES never seen in training (a compositional address code generalises to unseen types; a topical type->page table does not),
scored with a z that is cluster-robust by type.
