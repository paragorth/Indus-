Question: if Voynich tokens are values (v78 C, v75 C-), is a page a table (calendar, astronomical, planetary hours, dosage, concordance) written row by row, with each word position or x-position a column whose values come from a column-specific set or step down the column?
Calibration: five real tables through the v72 surface (merge code + planted surface), scored after frozen E1c: a Julian kalendar (computus columns + real kalendar verses from Hampson 1841, archive.org), Alfonsine mean motions (Alfonsine daily rates, 13 cells), planetary hours + unequal-hour lengths, an Isidore concordance, an Antidotarium dosage list (quantities semi-planted); each also with 15% of cells dropped, and each written column by column. Negatives: Isidore, Brumati, German prose; SELFCIT, SC10, MK2, JUNC, STACK, WSHUF fitted to ZL3b. Kill null for every corpus: interior words shuffled inside each line (first/last word, line mode and page vocabulary kept).

Grades:
- A (method): written through the Voynich-like surface, real medieval tables keep their columns (row-wise 0.03-2.3 bits/token beyond line mode, page vocabulary and line edges; transposed z 8-49), and both the column count and the period are read back; prose and five non-vertical generators give zero (V-80.1.1-3, 2.1-2, 3.1-3).
- B (negative): Voynich pages are not tables written as lines, in either direction. No column value sets, no stepping down columns, no recurring column lines, in the whole book, in either transcription, or in any section (detection floor: a careless Alfonsine copy with 15% of cells lost) (V-80.1.4-5, 2.3-4, 3.4).
- B: what a Voynich line knows about position is its edges (page-specific first word, the line-start layer of v79) plus a weak drift (C below).
- C (guess): inside the line there is a smooth ordering drift, not slots: ch-initial classes (chy-, cho-, cha-) lean early, classes with p/f/k/t gallows lean late (quire 20, held out, both transcriptions; +0.016 bits/token in the book, 3x Isidore, absent in generators). Would support: the same lean on a third transcription and stronger in long lines; would kill: a line-aware generator with a glyph-position gradient giving +0.016.
- Demoted: v78's 'value in a row' reading -> C- for a TABLE row: if tokens are values, they are not laid out in table columns. The notation-like reading (a symbol stream with no neighbour ban) is untouched.
Meaning extraction: none. The table frame is closed for row, column-by-column and slot-free (HMM) layouts; any content in Voynich lines is not organised by position the way any tested table is. Not cracked.
