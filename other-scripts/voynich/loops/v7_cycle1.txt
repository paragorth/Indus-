# v7 cycle 1 -- "every word is a number": does a positional-digit reading of the slot grammar make Voynich lines behave like numeric tables?
# Prior work checked (web, 4 Oct 2026): voynich.ninja threads propose Roman-numeral or numeric-index ciphers (thread 5798 etc.), hand-assigned
#   glyph values, no fitted search and no planted-table control. Not repeated here: no Roman numerals, no hand values, everything fitted and controlled.
# Scripts: tools/v7_numlib.py (slot model, encoding, scoring, annealing), tools/v7_planted.py (positive control), tools/v7_cycle1.py.
# Results: data/results/v7_cycle1.json, .log; slot models cached in data/derived/v7_slotmodels.json.
# Pipeline (same for every corpus): learn the corpus's own glyph order; cut it into K = 4 bins (= digit slots) choosing the cuts that maximise the
#   share of tokens whose filler in each slot is among that slot's 10 commonest (empty counts); reading = one injective filler->digit map per
#   slot, value = 4-digit number, leftmost slot most significant. Score J = mono3 + colmono3 + 5*(cdiff + colcdiff) + 5*sum, where mono3 = share of
#   consecutive in-line triples moving in one direction, cdiff = exact nonzero constant difference, col* = same down a column (same word position,
#   3 consecutive lines of one paragraph), sum = last number of line equals sum of the earlier ones. Annealing 10,000 swaps, fit on even paragraphs,
#   J reported on held-out odd paragraphs. Nulls with the same slot model: global word shuffle, within-line shuffle; plus 200 random digit maps.
