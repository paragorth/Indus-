PE-56 cycle 3: DISSECT EVERY RESIDUE WITH ORACLE FORGERS (what knowledge would the forger have needed?)
Date 6 Oct 2026. Scripts: tools/pe56_c3.py, tools/pe56_report3.py. Checkpoints data/pe56_ckpt/c3_*.json.
Idea: a residue is only interesting if we know WHAT the forgers lacked. Each cycle-1 residue (ensemble-mean
p < 1e-3; 48 in PE, 11-92 in the controls) is re-scored against four oracle forgers, each handed one kind of real
knowledge (30 draws per tablet; HDR and TOPIC trained on the other 4 folds):
  PERM  the real tablet with its own entry lines (string + numeral) permuted, header in place;
  VPERM the real tablet with its numerals permuted among its own entries;
  HDR   the real header copied, entries drawn from tablets whose header starts with the same sign;
  TOPIC the real header copied, entries dealt from 1-3 other real tablets sharing a header sign.
Type (oracle 'explains' a residue when p(R | oracle) >= 1e-3): ORDER = survives PERM; BINDING = survives
VPERM only; ORDER+BIND = both (arithmetic totals); HEADER = explained by HDR; TOPIC = explained by TOPIC;
TABLET = explained by own-tablet permutation but by no forger built from other tablets (a whole-tablet set).
Caveat: HDR / TOPIC copy the header and numeral entries only, so closing non-numeral lines (Ur III dates) are
TABLET by construction.
