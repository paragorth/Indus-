pe74 cycle 1: RESTORATION AUDIT. A parser that knows what the editor restored (6 Oct 2026).
Scripts: tools/pe74_parse.py (parser, load(mode)), tools/pe74_c1.py (validation and counts), tools/pe74_harness.py (runs older loops' code on a filtered corpus). Gold lines: data/pe74_gold_lines.json. Checkpoint: data/pe74_ckpt/c1.json (git-ignored).
Why: pe73 found that build_corpus.py strips '[ ]', '< >', '#', '?' and keeps every token as read; P009296's key N14 in pe42 is an editorial restoration. CDLI ATF here uses '[..]' (restored, may span several tokens and sit inside a compound, e.g. 'M362#+[x]'), '<..>' (supplied by the editor: the scribe omitted it), '#' (damaged), '?' (uncertain) and '!' (sic). No half-brackets occur in this corpus.
Status per token, worst mark wins: restored = supplied > uncertain ('#?' counts as uncertain) > damaged > read ('!' only = read). Modes: all (old behaviour), rd (read + damaged), r (read only). A line that loses a token in rd / r is marked lacuna and gets a '[...]' in raw, so older code's clean / numclean flags drop it from arithmetic.
