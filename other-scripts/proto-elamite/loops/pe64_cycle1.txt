pe64 RECONSTRUCT THE RATION LADDER FROM EVERY PER-HEAD RATE, cycle 1 (6 Oct 2026)
Tools: tools/pe64_lib.py, tools/pe64_c1.py, tools/pe64_sum.py, tools/pe64_runq.sh. Checkpoints: data/pe64_ckpt/c1_*.json.
Idea: every count line followed (or preceded, or totalled, or echoed on a dossier neighbour) by a capacity line gives
one candidate per-unit rate.  1,022,812 rate-detection rules per run (322,812 exhaustive grid: 7 scopes x 3 target
filters [any / M288 / not M288] x 2 readings of N01-only lines x count >= 1/2/3 x exact-or-any x 61 source signs x
21 target signs; plus 700,000 random rules with random OR-sets of 2-5 source signs).  Score = distinct tablets that
show the rule's commonest rate.  Discovery on one half of the tablets (hash split), survivors = k >= max of 6
swap-null scores at the same rate + 2 and >= 2x their mean + 2.  Every surviving rate tested on the other half by
three selectors (union of <= 400 survivor rules; best grid rule; best rule), 200 swap nulls + 20 re-pair nulls.
Validated = p_swap <= 0.005 (floor) with >= 2 held-out tablets.  Both split directions run.
Nulls: SWAP = capacity values dealt from other tablets with the same notation shape (keeps PE's own round numbers);
REPAIR = counts and capacities re-dealt within the tablet (reported, but it cannot move single-pair tablets, so it is
not used to validate).  Controls: Ur III ration lists with the '-ta' rate hidden (count line, then 'sze-bi' line =
n x rate, plus the tablet's other capacity lines as distractors; 1,628 tablets; and a 120-tablet subsample);
proto-cuneiform (3,145 admin tablets, ŠE capacity system); planted 3-rung ladder (20/40/80 N39C on 10 tablets each,
keyed to 3 count-line signs) in a swap-null PE corpus; a swap-null PE corpus run as if real (false-positive rate).
