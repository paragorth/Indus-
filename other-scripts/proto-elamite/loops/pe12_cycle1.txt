pe12 cycle 1 (4 Oct 2026): "THE ENTRIES CARRY CHECK DIGITS" -- calibration of the search engine.
Engine (tools/pe12_common.py, pe12_search.py): a SLOT sign (first, last = before-number, first/last of multi-sign entries,
first sign after the header) is predicted from the rest of the entry by a lookup table P(sign | f(entry), system) fitted on
50% of tablets; ~26,000 hypotheses per slot (300 single features: value mod 2-13, digit counts mod k, digit sums, running
tablet sums mod k, size bands, thresholds, top numeral code, sign count, other-slot sign, header, line index; 20,000 RANDOM
sparse modular hashes of the numeral digits/values; 6,000 random feature pairs); top hypotheses chosen on 25% of tablets,
tested on the last 25%; 2 splits. Statistic = held-out gain (bits/entry) over P(sign | tablet type, system) of the
B-best hypothesis per family. Nulls re-run the whole search with the slot sign shuffled: STRICT within (tablet, system),
LOOSE within (tablet type, system), SIZEM within (tablet type, system, log2 value band, fraction flag). 10 replicates each
(p floor 0.091; z = (real - null mean) / null sd). Script tools/pe12_cycle1.py; numbers data/pe12_cycle1.json, .log.
Prior art: Born et al. 2023 (CAWL) predict the NUMBER SYSTEM from signs (bootstrapped classifier); nobody has searched for a
sign predicted by the number BEYOND its system, or for check marks (web search; LITERATURE.md; FINDINGS.md; STRATEGIES.md).

Verdict cycle 1: the engine finds a check sign planted in 10% of entries (z ~10) and recovers a real ancient size-class
marker (Ur III units, z 43). It finds no arithmetic structure in proto-cuneiform beyond size. Weak point: modular hashes soak
up size signals, so any PE "check digit" must survive a fine-size-conditioned test (cycle 2b) before it counts.
