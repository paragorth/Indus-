# pe46 cycle 1: THE "NAMES" ARE SERIAL NUMBERS. Calibrating a slot-schema code detector (5 Oct 2026)
Idea (arrow in the dark): the multi-sign strings that open PE entries are administrative codes (account numbers, postcodes), not personal names: each slot has its own small alphabet and encodes one attribute (office, unit, serial). Not in LITERATURE.md, FINDINGS or STRATEGIES; pe4 tested a factorial item-description MDL on the same strings, but with no external variables, no tablet context and no office/serial signature; quick web search found no slot-code search on PE.
Method (tools/pe46_lib.py, pe46_cycle1.py): 3,000 random slot schemas per corpus (2-4 slots cut by fixed / from-end / sign-set / run rules, random slot alphabets of 6-48 values) fitted on half the tablets, top 20 re-scored on the held-out half (two tablet splits). Score CODE = field purity FS (different slots track different external variables: tablet id + P-number batch / class or commodity sign / line order / previous entry; shuffle-corrected MI) + office-and-serial signature OS (one slot repeats on a tablet beyond chance, another repeats less than chance; Poisson z) - conditional slot dependence. Strings: PE entry signs before the final class sign, length >= 2 (1,732 strings, 713 tablets).
Nulls: signs shuffled within strings (~sig), strings shuffled across tablets (~tab), sign-bigram Markov resynthesis (~mkv). Controls at PE size: planted 3-slot code on the real PE tablet frame (office per tablet, unit tracking the class sign, sequential serial; values in PE signs); HTS tariff numbers in opaque 2-digit symbols on pseudo-invoices (real hierarchical code); Ur III Drehem livestock attribute strings (real structured descriptions); Ur III Drehem personal names (must NOT look like codes); Linear B first words of personnel entries (names) and full pre-logogram designations (name + place / office), DAMOS.
