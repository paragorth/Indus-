Library actually obtained (type in brackets; all openly licensed or public domain; sizes before length matching):
  L language writing: ur3_words 6,381 (CDLI seal legends, words, deduplicated); ur3_syll 20,392 (same legends as syllables, one per
     impression); ur3_names_syll 24,494 (line-1 owner names, syllables); linb_words 13,170 and linb_syll 13,170 (DAMOS Linear B lines);
     latin_edh 6,000 (EDH Italy, words); runes_words 613 (RunesDB.de TEI, CC BY-SA; BELOW the 1,000 bar, test only).
  D designed code: heraldry 31,814 (Rietstap blazons); icd10 74,260 (CMS ICD-10-CM codes, characters); hts 29,861 (USITC tariff numbers,
     2-digit groups); unicode_names 20,000 (character names, words); aircraft_reg 20,000 (OpenSky registrations, characters).
  G grammar without language: chess_eco 3,815 (lichess openings, CC0, moves); chords 20,000 (Chordonomicon song sections, CC BY-NC).
  A accounting / tally: khipu 6,561 (OKR cord clusters); proto_elamite 10,836 (CDLI lines); proto_cuneiform 53,295 (CDLI lang qpc lines, new).
  I Indus: seq_raw / seq_strong / seq_all (5,369 objects, merged-corpus-canonical.json, S-DARK-23 caution) and IM77 (2,813 texts, lines
     joined in reading order). X controls: slot-shuffled Indus (S310 parse; tokens permuted across texts within slot label x length),
     Markov-2 synthetic Indus, bigram synthetic Indus.
  NOT obtained (no open machine-readable source reachable; skipped, not faked): Egyptian titularies, Old Persian / Aramaic / Phoenician
     seals, oracle-bone or bronze texts, merchant / masons / potters marks, real ISBN lists, vehicle plates, Dewey; Rundata (GitHub mirror
     and FAA registry returned 403 from this session).

Battery = the repository's own code paths: strat_codelibrary.battery (18 stats: Zipf slope, positional entropies, closed-class ends,
bigram MI, h2/H1, uniq_vs_bigram = S321 statistic, repeat ratio, nesting, frames, vocabulary growth) + dark_loop19 pair census with BH
(fixed / free pair shares, anagram rate; functions copied verbatim) + dark_loop25 complement hubs, hub mobility, free use and
determinative loyalty (compact port) + slot exclusivity, top-10 closer / opener share, second / penultimate position entropies, numeral
share / end bias / run share, and a held-out slot-model-vs-bigram-model preference (bits per token). Every corpus subsampled to the
Indus length histogram (2-13 signs, cap 3,000) eight times; length features excluded from the classifier.

Results (loop32_classify.txt)
1. Indus replicates its earlier numbers inside the joint battery: fixed pair share 0.70 (0.71 raw/strong/all, 0.65 IM77), anagram rate
   0.03-0.04, uniq_vs_bigram 0.82-0.86, hubs 0.02-0.07 per sign, det_loy50_max 0.30-0.37, slot model beats bigram by 0.21-0.50 bits.
   All three merge levels agree to the second decimal; IM77 differs most on hubs (0.10) and slot preference (+0.50).
2. First classifier (36 features, 16 training corpora, L2 multinomial logistic regression, class-balanced, leave-one-CORPUS-out):
   accuracy 7/16 = 0.44 = majority-class chance; label-permutation null mean 0.30, 95th pct 0.62, P(null >= obs) = 0.195.
   Nearest-centroid 0.50, 1-NN 0.38. Wrong: khipu -> D, proto_cuneiform -> D, proto_elamite -> L, heraldry -> L, hts -> A,
   unicode_names -> L, chords -> A, linb_syll -> D, ur3_words -> D. So the three "known types" are NOT separable by this battery when a
   whole system is held out: the within-class spread (characters vs words vs syllables; Zipf slopes -0.6 to -1.8) is as large as the
   between-class spread. The classifier's Indus verdict (P(A) = 0.91-0.92 on all three levels and IM77, P(D) = 0.00) is therefore an
   OVERCONFIDENT output of an uncalibrated model and is not reported as a result; the controls also fail the pre-set requirement
   (slot-shuffled Indus -> A 0.76, not D; Markov-2 -> 0.50/0.50 L vs A; bigram -> L 0.54).
3. Nearest reference corpora of Indus in standardised feature space (model-free): proto_cuneiform 4.2-4.7, linb_syll 4.8-4.9,
   ur3_names_syll 5.0-5.2, proto_elamite 5.2, ur3_syll 5.4-5.6 (same order at raw / strong / all; IM77 puts ur3_syll second). The three
   synthetic Indus controls sit nearest ur3_syll / linb_syll (4.2-4.4), i.e. the syllable-level language corpora are what a Markov
   corpus of Indus shape looks like, so nearness to them carries no typological information.
4. Univariate: the metric that most separates Indus from the language corpora is num_run_share (numeral followed by numeral: Indus 0.07,
   L 0.005, z +8; A 0.44), then num_end_bias (Indus numerals lean to the START, -0.26; L +0.28; A +0.08) and det_loy50_max (Indus 0.34
   vs L 0.66: no loyal class sign, S-DARK-25). CAUTION: three of the six L corpora have no numeral annotation at all (Ur III syllables,
   names, and the deduplicated words), so the numeral z-scores are inflated by annotation, not only by behaviour; cycle 2 must drop or
   equalise the numeral features before any claim.
Verdict: library and battery stand; the first joint classifier is at chance under leave-one-corpus-out and its Indus probabilities are
not usable. Next: nested feature selection, stronger regularisation, binary 'language writing or not', numeral features dropped.
